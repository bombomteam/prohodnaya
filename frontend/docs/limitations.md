# Ограничения и следующие шаги

## Что работает сейчас

- Собственные интерфейсы администратора, контролёра, рабочего и руководителя, адаптированные под компьютер, планшет и телефон.
- Демонстрационный сквозной сценарий входа/выхода с журналом, сменой, координатами, зональной картой и табелем в `localStorage` браузера.
- Камера через `getUserMedia`, геолокация через `watchPosition`, WebAuthn-вызовы в режиме API и документированный HTTP-контракт.
- Публичный статический демостенд и автоматическая сборка GitHub Pages.

## Что не выполнено по кейсу

- Нет бэкенда, БД, аутентификации пользователей и ролевого доступа. Демоданные не являются общими между устройствами и не переживают очистку браузера.
- Нет серверной проверки пригодности эталона, сравнения лиц и защищённого решения о проходе. Демопроход нельзя использовать как доказательство защиты от прохода за другого.
- Нет реального сервера WebAuthn, постоянного журнала и проверки принадлежности координат открытой смене.
- Нет серверной аналитики, модели, внешнего и локального провайдеров, инфраструктуры локальной модели и достоверных ответов помощника. В деморежиме помощник прямо сообщает, что недоступен.
- План площадки условный. Три предоставленных изображения показывают отдельные ориентиры под углом; реальная привязка зон к координатам ещё не подтверждена.
- GitHub Pages размещает только фронт. Для полного стенда потребуется отдельный сервер и HTTPS-доступ к нему с телефона.

## План следующих 10 часов команды

1. Согласовать сущности и маршруты API с бэкендом; заменить деморежим на API на интеграционном стенде.
2. Реализовать серверную регистрацию эталона, WebAuthn, сравнение лиц, атомарное потребление подтверждения, смены и аудит; прогнать попытки обхода.
3. Подключить реальные события и координаты к дашборду, маршрутам, зонам и табелю; согласовать часовой пояс и правила периодов.
4. Реализовать серверный слой модели, два провайдера и инфраструктуру локального запуска; проверить ответы на известных данных и пустые состояния.
5. Проверить весь сценарий на новых фотографиях и телефонах судей, подготовить общесистемную документацию запуска и защиты.
