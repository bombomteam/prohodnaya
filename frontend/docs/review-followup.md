# Исправления после проверки по обновлённым требованиям

Основание — [исходный обзор](../../docs/frontend-review.md) и схема «Keycloak только для операторов, ECDSA для рабочего».

| Проблема | Изменение | Граница проверки |
| --- | --- | --- |
| Все разделы для всех | Раздельная навигация admin/manager/controller и ключевого рабочего, проверки переходов | Роли протестированы локально; окончательные полномочия проверяет backend |
| Нет OIDC | Code + PKCE S256 через предложенные серверные auth-endpoints, вход/выход/refresh, access token только в памяти | Нужен реальный Keycloak с construction/panel/access-api |
| Dashboard рабочего/контролёра, административный реестр руководителя | Удалены лишние вызовы, добавлен GET /reports/people | Endpoint справочника должен реализовать backend |
| WebAuthn против решения ECDSA | Новый WebCrypto/IndexedDB адаптер enroll/подписи/locations | device-v1 — проект wire format, отключён по умолчанию до сверки 01–08 |
| Ввод и камера уничтожаются render | view.js обновляет DOM и сохраняет существующие элементы | Ввод проверен браузером; физическая камера не проверялась |

| Неполное управление людьми | UI выпуска enroll-кода, отзыва ключа и деактивации; запрет деактивации внутри | Реальные endpoint и серверные ограничения ещё нужны |
| Руководитель может править план | Настройка показана только admin | Прямой PUT обязан отклонять backend |
| План только условная девятка | На экране только три зоны из материалов кейса; серверный план с полигонами и маршрутом отображается при наличии геопривязки | Реальная схема, координатная калибровка и формат хранения требуют backend |
| Нет таймаута и идемпотентного ключа | 15 секунд, ошибки 401/403, стабильный Idempotency-Key текущего прохода | Серверная идемпотентность и восстановление финального решения не реализуются фронтом |
| Разные часовые пояса | Общая настройка timeZone для дат/времени | Должна совпадать с площадкой на backend |
| Только пять цветов | Цвета генерируются по числу маршрутов | При большом числе людей всё равно полезно отдельное выделение маршрута |
| Новые правила запрещают зависимости | Чистые ES-модули, статическое копирование новых файлов | Docker и CI сохранены из main; Docker здесь не запускался |

## Выполненные проверки

- `npm test`: три теста — матрица ролей, криптографическая привязка подписи к контексту и неизвлекаемость ключа, существующий демосценарий.
- `npm run build:pages`: статический артефакт создан без установки зависимостей.
- Временный браузерный прогон через Edge (скрипт и пакеты используются только для проверки и не входят в зависимости приложения): навигация ролей, read-only manager, сохранение ввода при обновлении, сброс фото, размеры 360/768/1280, отсутствие pageerror.
- Тот же браузерный тест: настоящий браузерный CryptoKey хранится в IndexedDB, серверный mock проверяет ECDSA регистрации и GET /worker/me, профиль доступен после reload; запросов /dashboard и /employees от рабочего нет.

## Что остаётся

Подтвердить wire format с 01–08 и backend до включения device-v1 сервером через /worker/config. Пройти живой IAM, разные устройства, камера, подписи/nonce/лицо на сервере, план из материалов, PostgreSQL, реальная модель и два провайдера. Окончательные решения backend после потери ответа требуют отдельного recovery-контракта. Текущие тесты не доказывают невозможность пройти за другого.

Существующие шаблоны обновляются через view.js без фреймворка. Демо по-прежнему локальное и явно обозначенное. Самописный JWT fallback не включён: решения команды о переключении сейчас нет.
