# Проходная

В этой папке есть фронтенд для администратора, контролёра, рабочего и руководителя. Бэкенд команда подключит по контракту [docs/frontend-api.md](docs/frontend-api.md).

Публичное демо интерфейса из GitHub: https://bombomteam.github.io/prohodnaya/. На сайте включён только демонстрационный режим с вымышленными данными. Публикация фронта не означает, что серверная часть готова.

Документация: [запуск](docs/launch.md), [архитектура](docs/architecture.md), [API-контракт](docs/frontend-api.md), [решения](docs/decisions.md), [ограничения](docs/limitations.md), [использование ИИ](docs/ai-usage.md), [деплой](docs/deployment.md).

Docker: из корня репозитория выполните `docker build -t prohodnaya-frontend:local ./frontend`, затем `docker run --rm -p 8080:8080 prohodnaya-frontend:local`. Параметры для подключения API и HTTPS описаны в [инструкции по деплою](docs/deployment.md).

## Быстрый запуск фронтенда

Нужен Python 3. Из папки `frontend`:

```powershell
python -m http.server 8080
```

Откройте `http://localhost:8080`. Установка npm-пакетов не требуется. Другой статический HTTP-сервер также подойдёт. Не открывайте `index.html` через `file://`: ES-модули и доступ к устройствам браузера могут не работать.

В `config.js` сейчас выбран `mode: "demo"`. Этот режим нужен только для разработки интерфейса: тестовые записи и имитируемые результаты хранятся в `localStorage` браузера. Жёлтая плашка на каждой странице явно сообщает об этом. Демо не является рабочей проверкой лица и не закрывает требования кейса к серверу.

Для подключения бэкенда установите в `config.js` `mode: "api"` и `apiBaseUrl`, затем реализуйте или сопоставьте маршруты из [контракта](docs/frontend-api.md). В режиме API фронт не подставляет тестовые цифры и не принимает решение о проходе. Камера, WebAuthn и геолокация требуют `localhost` или HTTPS. Для телефона на другом устройстве нужен HTTPS-стенд и доступ к серверу с этого устройства.

## Что уже есть в интерфейсе

- Сотрудники: список, поиск, добавление и редактирование с загрузкой эталонного фото.
- Проходная: вход/выход, одноразовый запрос, ожидание подтверждения телефона, снимок с камеры, серверный результат и причина отказа.
- Телефон рабочего: привязка устройства WebAuthn в режиме API, подтверждение запроса и отправка координат во время открытой смены.
- Руководитель: текущие люди внутри, журнал, зональная карта и маршруты с общими фильтрами, табель, вопросы помощнику и сводка.

Схема площадки пока условная сетка 3 × 3 с редактируемыми названиями зон и прямоугольной привязкой координат. В подписях использованы видимые на предоставленных снимках ориентиры: котлован, бетономешалка и место для курения. Снимки сделаны под углом и не дают точной географической привязки или взаимного расположения всех зон. Расположение зон и примерные координатные границы деморежима нужно согласовать с командой перед реальной аналитикой.

## Важно для защиты

Сейчас нет отдельного сервера, постоянной БД и серверной проверки лица. Реальный допуск по кейсу **не выполнен**. Нужны интеграция, проверки чужого лица и повторного подтверждения, реальные данные аналитики и работающий слой модели. Не показывайте деморежим как доказательство безопасности.
