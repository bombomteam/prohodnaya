# Этап 3. Выбор стека

Все числа посчитаны общим скриптом `face/eval/run_eval.py` на **первом пакете** (78 файлов, разметка `face/eval/labels.csv`). Отчёты лежат в `face/eval/out/*/summary.json` (не в Git).

- Второй пакет — проверка без подстройки, результаты отдельно (раздел «Второй пакет»).
- Данных с айфона пока нет.
- Замеры скорости шумные: параллельно работали до 9 агентов, нагрузка 27–100 при 16 vCPU. Чистый замер — за агентом-проверяющим.

## Решение

| Задача | Выбор | Лицензия |
| --- | --- | --- |
| Детекция лица + 5 точек | **SCRFD det_10g** (InsightFace) | Код MIT, веса — только некоммерческие исследования (риск, см. ниже) |
| Сравнение 1:1 | **ArcFace glintr100** (InsightFace, набор antelopev2), косинус, **порог 0,68** | То же |
| Защита от «прошёл по телефону коллеги» | **Правило галереи:** заявленный эталон должен быть ближе, чем эталоны всех других сотрудников (поле `gallery` в `verify`) | — |
| Подсчёт людей | **YOLOX-S** (Megvii) + правило «в зоне прохода»; запасной YOLOX-Tiny | Apache 2.0 (обучен на COCO) |
| Пассивный антиспуфинг | **MiniFASNet** V2 + V1SE, рамка от SCRFD как есть, порог 0,5, медиана по кадрам окна | Apache 2.0 |
| «Живость» по нескольким кадрам | Агент ещё работает; итог добавлю | — |
| Запасной вариант лиц | OpenCV YuNet + SFace (в образе, но не по умолчанию) | MIT / Apache 2.0 |

Форма модуля подтверждена:

- отдельный контейнер `face`, HTTP API во внутренней сети, без своего хранилища;
- эмбеддинг эталона и `model_version` хранит бэкенд.

Контракт — [api.md](api.md).

## Распознавание: цифры по кандидатам (первый пакет)

Свои пары считаются только по кадрам, которые прошли качество. Число таких кадров зависит от детектора, отсюда разные знаменатели.

| | OpenCV SFace | InsightFace w600k_r50 | **InsightFace glintr100** |
| --- | --- | --- | --- |
| Штатный порог (источник) | 0,363 (opencv_zoo) | 0,40 (код insightface; официального нет) | 0,40 |
| Ложных совпадений на штатном пороге | **80 / 495**, Кимы 12/12 | **28 / 468**, Кимы 11/11, Гаджиев/Эргашев 10/11 | **32 / 468**, Кимы 11/11, Гаджиев/Эргашев 10/11 |
| Мин. своё − макс. чужое (зазор) | 0,456 − 0,762 = −0,306 | 0,562 − 0,734 = −0,171 | 0,542 − 0,661 = **−0,119** |
| Ноль ложных: порог и сколько своих | > 0,762 → 35 / 49 | > 0,734 → 33 / 46 | > 0,661 → **43 / 46** |
| Непригодные кадры → верная причина | 2 / 2 | 2 / 2 | 2 / 2 |
| Плохие эталоны отклонены (синтетика) | 42 / 53 (перевёрнутые на 180° — 2/10) | 53 / 53 | 53 / 53 (тот же детектор) |
| Время на кадр, медиана (шумно) | детекция 43 + эмбеддинг 19 мс | детекция 188 + эмбеддинг 225 мс | эмбеддинг 604 мс (против 397 у w600k_r50 в тех же условиях) |

**Вывод:**

- На штатных порогах **все три модели пропускают двойников.** Без своего порога «пройти за другого» удаётся.
- SFace отпадает.
- glintr100 даёт лучший зазор и больше всего своих кадров при нуле ложных.

## Порог 0,68 и правило галереи

Порог подбирался **только на первом пакете**, по худшему случаю. Цифры ниже пересчитаны из `pairs.csv`: 52 своих кадра, прошедших качество (`match` + `either`), и 468 чужих пар.

| glintr100 | Своих принято | Ложных: атакующий **есть** в базе (коллега) | Ложных: атакующего **нет** в базе (человек судей) |
| --- | --- | --- | --- |
| Только порог 0,40 | 52 / 52 | 32 | 32 |
| Только порог 0,66 | 48 / 52 | 1 | 1 |
| Только порог **0,68** | **46 / 52** | **0** | **0** |
| Порог 0,68 + галерея | 46 / 52 | 0 | 0 |
| Порог 0,40 + галерея | 52 / 52 | 0 | 27 (Кимы 11) |

- **Порог 0,68** — первый на сетке с нулём ложных для человека вне базы. Зазор над самым похожим чужим (0,661) — всего 0,019. Это главный риск, проверяется на втором пакете.
- **Галерея** нужна как второй барьер для сценария кейса «отмечаются за товарища»: там атакующий — тоже сотрудник, и его эталон есть в базе. С галереей ложных совпадений коллег нет даже на низком пороге.
- **6 своих кадров из 52 не проходят по порогу.** В видео модуль берёт лучший кадр окна, поэтому живых отказов будет меньше. Ложный отказ означает «пройдите ещё раз», ложный пропуск — снятие с конкурса, поэтому выбираем строгий порог.
- Для сравнения: w600k_r50 на 0,68 даёт 3 ложных для человека вне базы, на 0,70 — 1.

## Подсчёт людей

- **YOLOX-S с правилом «в зоне прохода»:**
  - на кадрах пакета ровно 1 человек — 66 / 66;
  - синтетика «двое рядом» → 2: 10 / 10;
  - «один на сером поле» → 1: 10 / 10;
  - прохожий далеко на фоне не считается: 29 / 29.
- Ложных «двое» на 174 кадрах 1280×720 — 0.
- Время ~80 мс на кадр (4 потока, нагрузка 7).
- Правило подсчёта:
  - рамки с уверенностью ниже 0,5 и дубли не считаются;
  - фигура ниже 25% высоты кадра не считается;
  - второй человек должен быть того же масштаба, что главный: корень из отношения площадей не меньше 0,6;
  - «двое» — только на 2 кадрах подряд.
- Итог = максимум из «людей в зоне» и лиц сопоставимого размера. Так считается и тот, кто стоит вплотную за спиной.
- Роликов «двое» с айфона нет — правило нужно подтвердить на них.

## Пассивный антиспуфинг (MiniFASNet)

- С рамкой SCRFD:
  - живые кадры проходной приняты 58 / 58 (минимум 0,523);
  - фото пропусков отклонены 10 / 10 (максимум 0,310).
- С рамкой YuNet один пропуск прошёл. Это ещё одна причина взять SCRFD.
- **Не ловит:** подмену кадра эталоном или старым кадром (это настоящие фото, live 0,93–1,0). Их закрывают проверки «кадр = эталон» и «повтор» по сходству и хешу.
  - Зазор у glintr100 тонкий: +0,043 для «кадр = эталон» и +0,017 для повтора.
  - В основном режиме (стример) браузер кадры не передаёт, и эта атака невозможна.
- Экраны и распечатки перед камерой **не проверены**: нужны ролики с айфона.
- Подробно — `face/eval/bench/minifasnet/NOTES.md`.

## Оборудование и задачи ИИ

| Ресурс | Как используем |
| --- | --- |
| CPU 16 vCPU, AVX-512 VNNI | Все модели через onnxruntime на CPU. Бюджет на попытку позволил взять более тяжёлую и точную glintr100 вместо w600k_r50: эмбеддинг считается только для ≤ 5 лучших кадров окна. Детекция лиц и людей — 4 кадра в секунду. Запас на ускорение — int8-квантование под VNNI |
| GPU A10 24 ГБ | По умолчанию не используется. Правило модуля: он обязан работать на CPU на чистой машине судей. A10 нужна и локальной модели помощника. Точность от GPU не меняется, растёт только скорость. Опция GPU (onnxruntime-gpu, 1–2 ГБ видеопамяти) — по решению человека |
| iPhone 16 Pro, задняя камера | Поток 1080p в портрете по RTMP, анализ 4 к/с. На 0,6–1 м лицо ≥ 150 px — больше входа 112 px у моделей |

Задачи ИИ и чем закрыты:

| Задача | Чем закрыта |
| --- | --- |
| Найти лицо | SCRFD |
| Тот же ли человек | glintr100 + порог 0,68 + галерея |
| Сколько людей | YOLOX-S + правило зоны + лица |
| Живой ли | MiniFASNet по кадрам + «живость» по нескольким кадрам |
| Пригоден ли кадр или эталон | Геометрия 5 точек, резкость, свет, закрытое лицо |

## Риски

- **Лицензия InsightFace:** веса только для некоммерческих исследований. Для хакатона допустимо. Для внедрения нужна коммерческая лицензия InsightFace или замена модели: архитектура позволяет, меняются адаптер и `model_version`, эталоны перерегистрируются. Свободная альтернатива (SFace) на наших данных не держит двойников.
- **Тонкий зазор порога** (0,019 над самым похожим чужим). Проверяем на втором пакете и данных с айфона. Галерея страхует коллег, но не людей вне базы.
- **Оценка наклона головы по 5 точкам у SCRFD смещена** (~3° вверх относительно YuNet). Из-за этого три улыбающихся кадра и фронтальный эталон получили ложное «повернитесь». Ядро калибрует ноль.
- **Перевёрнутые эталоны:** SCRFD находит лицо и на 180°. Отклоняем по наклону и дополнительной проверке ориентации.
- **Нет данных с айфона:** не проверены экраны, распечатки, ролики «двое» и задержка.
