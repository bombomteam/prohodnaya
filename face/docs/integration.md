# Стык модуля лиц с фронтом, бэкендом и инфраструктурой

Для разработчиков и их ИИ-ассистентов. Модуль `face/` ведёт ответственный за инфраструктуру: в `face/` не правьте, нужные изменения описывайте ему.

Статус: **черновик до `face/docs/api.md`**. Точные поля запросов и ответов появятся там в начале этапа 4. Здесь — что меняется у вас и почему.

## Что изменилось

- **Камера на входе снимает видео.**
  - На хакатоне её роль играет iPhone 16 Pro (задняя камера) как IP-камера: приложение Larix Broadcaster публикует поток по RTMP на медиасервер MediaMTX.
  - Модуль `face` читает поток по RTSP. Так же будет работать настоящая IP-камера: меняется только адрес.
  - Браузер контролёра в передаче кадров не участвует, поэтому подменить кадр через инструменты разработчика нельзя.
- **Что модуль делает по видео:**
  1. Считает людей в кадре. Двое и больше → «проходите по одному».
  2. Сравнивает лицо с эталоном конкретного человека, который предъявил подтверждение с телефона (1:1).
  3. По нескольким кадрам проверяет «живость»: живой человек, а не фото или экран.
- Модуль возвращает факты. **Решение о проходе принимает бэкенд** вместе с проверкой подписи телефона.
- **Одиночный снимок** (`faceImage`, как сейчас) остаётся запасным режимом: это «видео из одного кадра».
- В [docs/system-workflow.md](../../docs/system-workflow.md) строка «React: проходная … получает кадр камеры» для основного режима устарела: кадры идут со стримера, а не из браузера.

## Бэкенд

- **Регистрация.**
  - `POST /employees` (`referencePhoto`): бэкенд передаёт фото в модуль на проверку эталона **до сохранения**.
  - Ответ «не принят» → запись не создаётся. Фронту уходит `photoCheck` с кодом и текстом причины.
  - Ответ «принят» → в PostgreSQL сохраняется эмбеддинг эталона и `model_version`. Модуль своего хранилища не имеет.
- **Проход.**
  - После проверки подписи телефона бэкенд вызывает у модуля проверку человека X на камере C за окно попытки. В запросе: `camera_id`, начало и конец окна по времени сервера, эмбеддинг эталона с версией модели, `attempt_id`.
  - Окно начинается с создания попытки и заканчивается через 2–3 с после подтверждения: это запас на задержку потока.
  - Запасной режим — тот же вызов, но с кадром `faceImage` вместо окна.
- **Решение.** Проход только если подпись телефона верна **и** модуль вернул `ok`.
  - Ошибка, таймаут (ориентир 5 с) или недоступность модуля → отказ «Сбой проверки лица. Проход не разрешён». Попытка пишется в журнал.
  - Поля `match`, `verified`, `allowed` от клиента не принимать.
- **Причины отказа.** Модуль отдаёт код и текст для человека, таблица — в [02-tasks.md](02-tasks.md). Текст показывать пользователю, код писать в журнал.
- **Перерегистрация.** Если у эталона другая `model_version`, модуль ответит `reference_outdated`: эталон нужно загрузить заново.

## Фронтенд

- **Проходная, основной режим:** камера в браузере не нужна, видео идёт со стримера.
- **Проходная, запасной режим «снимок»:** `facingMode: "environment"` (задняя камера; сейчас стоит `"user"`), не ниже 1280×720, JPEG 0.88, кадр не зеркалить и не уменьшать.
- **Отказы:** показывать текст причины из ответа сервера, коды — только в журнале.
- **Регистрация:** при отказе эталона показывать причину из `photoCheck` («на фото несколько лиц», «лицо не найдено»…).
- **Живой просмотр камеры для контролёра.** Видео в реальном времени с рамками вокруг людей и их числом, отдельная вкладка — с распознаванием лиц. Страницу отдаёт модуль через бэкенд. Как встроить (ссылка или iframe) — после `api.md`.

## Инфраструктура (`compose.yaml`, `.env.example`)

- **Сервис медиасервера MediaMTX** (MIT, образ `bluenviron/mediamtx`):
  - наружу только порт приёма потока `1935/tcp` (RTMP);
  - публикация по паролю из переменной окружения;
  - RTSP `8554` — только во внутренней сети.
  - Рабочий конфиг для тестов: [face/tools/camera/mediamtx.yml](../tools/camera/mediamtx.yml).
- **Сервис `face`:**
  - без `ports:`, только внутренняя сеть;
  - общий блок `x-hardened`: файловая система только для чтения, не root, `tmpfs /tmp`;
  - веса моделей внутри образа;
  - адрес потока в переменной, например `FACE_CAMERA_URL=rtsp://<медиасервер>:8554/live/gate`.
- **`.env.example`:** пароль публикации камеры, например `CAMERA_PUBLISH_PASS=`.
- Готовый фрагмент сервиса для `compose.yaml` будет в `face/docs/` на этапе 5.
- Сейчас MediaMTX запущен временно, вне `compose.yaml`, только для тестов (`face/tools/camera/run_mediamtx.sh`).
