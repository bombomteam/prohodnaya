## Если останется время

- Активная проверка: модуль просит «поверните голову» и сверяет движение. Сильнее против видео на экране, но нужна правка фронта.
- SRT вместо RTMP и замер задержки «камера → сервер» по секундомеру в кадре.
- WebRTC-просмотр с рамками поверх плавного видео (MediaMTX отдаёт WebRTC, рамки по WebSocket).
- Несколько эталонов на человека (лучше для каски и очков).
- GPU (A10) для модуля — только если CPU не тянет 4 к/с на камеру.

## Не делаем

| Что | Почему |
| --- | --- |
| Обучение своих моделей | Запрещено правилами модуля; берём готовые |
| Облачные API распознавания | Персональные данные не уходят наружу; запрет кейса |
| Решение о проходе в модуле | Решает бэкенд вместе с подписью телефона |
| Хранение фото и эмбеддингов в модуле | Эталон и версию модели хранит бэкенд в PostgreSQL; модуль без состояния, кроме буфера кадров в памяти |
| Чтение пропусков и документов камерой | Удостоверение — подпись телефона; печатный пропуск им быть не может |
| Подсчёт людей на объекте | Это бэкенд по сменам; камера считает людей в кадре |
| Глубина (TrueDepth/LiDAR), ИК | В потоке со стримера их нет |
| Своё iOS-приложение, WebRTC-приём | Не успеваем; стример + RTSP уже работает |
| Логика по именам, папкам и файлам пакета | Подгонка под тест; запрещено |

## Решение: как считаем людей

**Детектором людей, лица — дополнительно.**

- Человек может стоять спиной, а лицо может быть закрыто — по одним лицам второго не увидим. Поэтому основа — детектор людей.
- В зоне прохода считаем только людей, которые близко к камере: рамка достаточно высокая относительно кадра или главного человека. Прохожие далеко на фоне не считаются. Точное правило и пороги — по цифрам этапа 3.
- Итоговое число = максимум из «людей в зоне» и «крупных лиц». Лицо считается, даже если тело обрезано кадром.
- В окне попытки берём максимум по кадрам: если хотя бы на нескольких кадрах подряд видно двоих — «проходите по одному». Одиночный ложный кадр не должен давать отказ; правило «≥ 2 кадров подряд» уточним на роликах.
- На эталоне «несколько людей» — второе заметное лицо **или** второй человек от детектора.

## Решение: причины отказа (код + человеческий текст)

Модуль возвращает код и текст. Бэкенд показывает текст пользователю, код пишет в журнал. Технические детали — только в серверный лог.

| Код | Текст для человека | Когда |
| --- | --- | --- |
| `ok` | — | Проверка пройдена |
| `no_face` | Лицо не найдено. Встаньте перед камерой. | Нет лица ни на одном кадре окна |
| `multiple_people` | В кадре несколько человек. Проходите по одному. | ≥ 2 человек в зоне прохода |
| `multiple_faces` | На фото несколько лиц. Нужен портрет одного человека. | Эталон |
| `turn_to_camera` | Повернитесь лицом к камере. | Профиль, спина, сильный наклон |
| `too_small` | Подойдите ближе к камере. / Лицо на фото слишком маленькое. | Кадр / эталон |
| `low_quality` | Кадр нечёткий или слишком тёмный. Встаньте под свет и не двигайтесь. | Смаз, темно, пересвет |
| `face_mismatch` | Лицо не совпадает с эталоном. | Сходство ниже порога |
| `spoof_suspected` | Не удалось подтвердить, что перед камерой живой человек. | Антиспуфинг или «живость» по кадрам |
| `frame_is_reference` | Кадр не с камеры: он совпадает с фото эталона. | Подмена кадра эталоном |
| `frame_replayed` | Этот кадр уже присылали. Нужен новый снимок. | Повтор кадра |
| `no_frames` | Нет видео с камеры за время попытки. | Камера молчит или окно пустое |
| `camera_unavailable` | Камера проходной недоступна. Проход не разрешён. | Поток упал |
| `bad_image` | Файл повреждён или это не изображение. | Битый файл, мусор |
| `unsupported_format` | Формат не поддерживается. Нужен JPEG, PNG или WEBP. | Другой формат |
| `too_large` | Файл слишком большой. | Превышен лимит |
| `reference_outdated` | Эталон снят старой версией модели, его нужно перезагрузить. | Версия модели эмбеддинга не совпала |
| `internal_error` | Сбой проверки лица. Проход не разрешён. | Любая внутренняя ошибка |

Сбой, таймаут или недоступность модуля бэкенд трактует как отказ.
