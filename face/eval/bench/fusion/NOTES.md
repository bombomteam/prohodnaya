# Слияние моделей и flip-TTA для сравнения 1:1: заметки прогона

Цель: увеличить запас над самыми похожими чужими (два Кима, Гаджиев/Эргашев) у glintr100. Подбор — только по первому пакету (`face/eval/labels.csv`), второй пакет — одна проверка выбранного варианта без подстройки.

## Файлы

| Файл | Что |
| --- | --- |
| `backend.py` | Адаптер для `run_eval.py`: SCRFD det_10g (как в `bench/insightface`) + одна или несколько ArcFace-моделей, flip-TTA. Переменные `FUSION_RECS`, `FUSION_WEIGHTS`, `FUSION_TTA`, `FUSION_DEVICE` (cpu/cuda), `FUSION_THREADS`, `FUSION_DET_SIZE` — см. docstring |
| `run_variants.sh` | Прогоны вариантов на первом пакете, `--similar` для обеих пар, `--no-timing` |
| `analyze.py` | Сводка по `pairs.csv`: зазор, порог для 0 ложных (шаг 0,01), Кимы, Г/Э; `--mix` — оффлайн-слияние двух прогонов со весом |
| `bench_embed.py` | Время детекции и эмбеддинга на 20 изображениях пакета (×2 прохода), CPU или CUDA |
| `.venv-gpu/` | Python 3.12 + `onnxruntime-gpu[cuda,cudnn]==1.31.0` + остальное из `bench/insightface/requirements.txt` (не в Git) |

Слияние: эмбеддинги моделей L2-нормируются и склеиваются, итог нормируется; косинус склейки = среднее косинусов моделей. TTA: эмбеддинг выровненного кропа + зеркального (батч из 2), сумма нормируется. Проверено: `FUSION_RECS=glintr100 FUSION_TTA=0` даёт тот же эмбеддинг, что `bench/insightface` с `INSIGHTFACE_REC=antelopev2` (косинус 1,0).

**Вывод по первому пакету:**

- **Слияние с w600k_r50 вредит.** Ошибка на Кимах у двух моделей не независимая: w600k_r50 ставит пару Кимов ещё ближе, среднее косинусов поднимает макс. чужое с 0,661 до 0,697–0,704. Своих при нуле ложных — 39–40 против 43.
- **Flip-TTA ничего не даёт.** Сдвигает вверх все сходства примерно одинаково: мин. своё +0,010, макс. чужое (Кимы) +0,012. Своих выше макс. чужого — те же 43/46. Запас над Кимами на пороге 0,68 падает с 0,019 до 0,007. Время эмбеддинга ×1,7.
- **Лучший вариант — glintr100 без TTA (текущий выбор), порог 0,68.** Зазор этими средствами не расширяется: двойников путают все ArcFace-модели одного семейства.

## GPU как опция

`.venv-gpu`, `FUSION_DEVICE=cuda`, арена `kSameAsRequested`, `gpu_mem_limit` 2 ГБ, `cudnn_conv_algo_search=HEURISTIC`. A10 до и после замера — 0 МиБ занято; пик процесса во время замера — 1127 МиБ (по `nvidia-smi`, с контекстом CUDA).

| | CPU, 4 потока (нагрузка ~8–18) | A10 |
| --- | --- | --- |
| Детекция SCRFD 640, медиана/p95, мс | 95–100 / 105–127 | 16–17 / 17–20 |
| Эмбеддинг glintr100, медиана/p95, мс | 511 / 530 | 13 / 20 |

Вывод: GPU ускоряет кадр с ~600 до ~30 мс (×20), точность не меняет. На CPU узкое место — эмбеддинг glintr100 (511 мс; w600k_r50 добавляет к нему лишь ~90 мс, т. е. glintr100 на CPU непропорционально медленный — кандидат на оптимизацию графа/int8). Включать GPU-режим стоит, если бюджет попытки не укладывается в ≤ 5 эмбеддингов на CPU; иначе не нужно. `onnxruntime-gpu` с CUDA/cuDNN из pip — ~3 ГБ в образе.
