# Оценка распознавания лиц: скрипт, разметка, контракт адаптеров

Один скрипт прогоняет любого кандидата (детектор и распознавание лиц, живость, подсчёт людей) по размеченным данным и считает одинаковые для всех цифры. Сравнение прогонов — `compare.py`.

Скрипт зависит **только от numpy и Pillow** (`requirements.txt`). `cv2` нужен лишь для роликов `.mp4/.mov`: импортируется лениво и есть в venv кандидатов. Запускается из venv кандидата, адаптеры подгружаются по пути.

## Запуск

```bash
# из корня репозитория, python — из venv кандидата
python face/eval/run_eval.py \
  --backend face/eval/bench/<name>/backend.py \
  [--liveness face/eval/bench/minifasnet/backend.py] \
  [--people face/eval/bench/people/backend.py] \
  [--seq-liveness face/eval/bench/seqlive/backend.py] \
  --labels face/eval/labels.csv [--labels ~/face-data/labels.csv] \
  --models face/models --out face/eval/out/<run> \
  [--threshold X] [--liveness-threshold X] [--people-threshold X] [--seq-threshold X] \
  [--quality gate.yaw_max=35 ...] [--similar "A|B"] \
  [--clip-fps 4] [--clip-max-frames 60] [--max-side 0] [--parallel N] [--no-timing]

python face/eval/compare.py face/eval/out/*/summary.json   # markdown-таблица в stdout
```

- `--threshold` и другие пороги заменяют значения по умолчанию из адаптера. Без них используется порог из документации модели.
- `--quality раздел.ключ=число` переопределяет порог качества (разделы `common`, `ref`, `gate`). Отчёт пишет, с какими значениями считал.
- `--similar "A|B"` задаёт пару похожих людей (по `subject`) для отдельного счёта. По умолчанию — два Кима из пакета. Это только отчёт, модуль по именам не ветвится.
- `--parallel N` дополнительно меряет пропускную способность в N потоках (до 32 кадров). Адаптер должен быть потокобезопасным, иначе в отчёте будут ошибки.
- `--max-side N` уменьшает вход до стороны N (по умолчанию 0, без уменьшения).

Самопроверка без моделей на фейковых адаптерах (результаты бессмысленны, проверяется только подсчёт):


## Разметка `labels.csv`

UTF-8, запятая, заголовок. Колонки:

| Колонка | Значение |
| --- | --- |
| `file` | Путь относительно папки, где лежит этот CSV. Для пакета: `../../case_prerekvizity/...`. Для ролика: файл `.mp4/.mov` или папка с кадрами JPEG/PNG/WEBP (по имени, по порядку) |
| `subject` | Тестовый идентификатор человека (для пакета — имя папки). Только для оценки. Эталон и кадры одного человека ищутся внутри одного файла разметки |
| `kind` | `reference` (эталон), `gate` (кадр проходной), `badge` (пропуск), `screen` (фото с экрана), `print` (распечатка), `no_person`, `multi_person`, `clip` (ролик) |
| `ref_expected` | `accept`, `reject`, `any` (результат в отчёт, но не ошибка) или пусто (как эталон не проверяется) |
| `gate_expected` | `match`, `unusable`, `either`, `spoof`, `multi_person`, `disputed` или пусто (см. ниже) |
| `people` | Ожидаемое число **живых** людей в кадре; пусто — неизвестно или спорно. Необязательная колонка |
| `tags` | Через `;`: `helmet, hat, hood, glasses, smile, grimace, tongue, hands, profile, back, wide_angle, dark, backlight, blur, small_face, occluded, borderline, two_faces` |
| `note` | Коротко по-русски, что на кадре. В отчёты не выводится |

Ожидания для кадра проходной (`gate_expected`):

- `match` — живой пригодный кадр, должен совпасть со своим эталоном. Любой другой исход — ложный отказ.
- `unusable` — профиль, спина, лицо закрыто, сильное искажение, смаз. Верно: «повернитесь к камере», «лицо не найдено», «низкое качество», «маленькое лицо» или «несколько лиц». Совпадение со своим допустимо (`lenient`). «Не совпадает» — ошибка причины. Совпадение с чужим — критично.
- `either` — пограничный кадр. Допустимо и «совпало», и причина качества. «Не совпадает» — ошибка.
- `spoof` — пропуск, экран, распечатка, ролик с фото. Должен быть отклонён любым статусом, кроме `match`.
- `multi_person` — двое и больше в кадре. Верно: `multiple_people` или `multiple_faces` («проходите по одному»). `match` — критично.
- `disputed` — спорный кадр: по виду нельзя решить, тот же ли это человек (сильная смена внешности или другой похожий человек) или живой ли кадр (возможно, переснят с экрана). Причина — в `note`. Такой кадр прогоняется как обычный, но не входит ни в успехи, ни в ошибки, ни в пары «свой/чужой», сетку порогов, честные пары для подмены и повтора и живые кадры для живости. В `summary.json` и `report.md` — отдельная группа `gate.disputed`: статус, сходство со своим эталоном, максимум по чужим и чей, liveness. Порог по таким кадрам не подбирается.

Смысл тегов, где он не очевиден: `wide_angle` — заметное искажение объектива на лице (у края кадра или очень близко); `dark` — ночь или тёмная сцена (лицо может быть подсвечено); `borderline` — спорный кадр, причина в `note`; `small_face` — лицо около 100 px; `two_faces` — рядом с живым лицом в кадре второе лицо на фото или экране.

Атака с чужим лицом на экране или фото размечается **двумя строками на один файл**: `subject` — тот, чьё лицо показано (заявленная личность, против неё атака), и `subject` — сам атакующий. Обе строки `spoof` (или `multi_person`, если в кадре двое живых). Так считается и «прошёл ли за другого», и «прошёл ли сам с подделкой в руках».

`people`: считаются только живые люди на месте. Фото на стендах, изображения на экране планшета и пропуске не считаются, но упоминаются в `note`: детектор людей может на них сработать. Если в кадре фигура, про которую нельзя сказать, человек это или отражение, `people` пустое.

## Контракт адаптеров

Файл `face/eval/bench/<name>/backend.py` загружается скриптом по пути (`importlib`). Его папка добавляется в `sys.path`, поэтому соседние модули импортировать можно.

```python
class Backend:
    name: str            # например "opencv-yunet-sface"
    model_version: str
    threshold: float     # порог косинусного сходства по умолчанию — из документации модели, НЕ подобранный на пакете
    def __init__(self, models_dir: pathlib.Path): ...   # веса берёт из models_dir/<name>/..., ничего не качает
    def detect(self, img: np.ndarray) -> list[dict]     # img: RGB uint8 HxWx3, уже после EXIF-поворота
        # dict: bbox=(x1,y1,x2,y2) px, score=0..1, kps=5x2 px в порядке:
        # глаз с меньшим x, глаз с большим x, нос, угол рта с меньшим x, угол рта с большим x
    def embed(self, img: np.ndarray, face: dict) -> np.ndarray   # L2-нормированный float32 1-D
class Liveness:          # опционально, отдельный файл через --liveness (антиспуфинг)
    name: str; model_version: str
    threshold: float     # порог «живое» по умолчанию
    def __init__(self, models_dir: pathlib.Path): ...
    def score(self, img: np.ndarray, face: dict) -> float        # вероятность «живое лицо» 0..1
```

Лицо для `Liveness` берётся из детектора основного `Backend`. В `embed` и `score` передаётся тот же словарь, что вернул `detect`, поэтому в нём можно держать свои служебные поля, например исходную строку детектора для выравнивания.

Дополнительные адаптеры (если не заданы, раздел отчёта пропускается):

```python
class PeopleDetector:            # --people face/eval/bench/people/backend.py
    name: str; model_version: str
    threshold: float             # порог уверенности по умолчанию
    def __init__(self, models_dir: pathlib.Path): ...
    def detect(self, img: np.ndarray) -> list[dict]   # RGB uint8; только люди: bbox=(x1,y1,x2,y2), score
class SequenceLiveness:          # --seq-liveness face/eval/bench/seqlive/backend.py
    name: str; model_version: str
    threshold: float
    def __init__(self, models_dir: pathlib.Path): ...
    def score(self, frames: list[np.ndarray], faces: list[dict | None]) -> dict
        # faces — лучшее лицо кадра от детектора Backend (или None); вернуть {"live": 0..1, "details": {имя: число}}
```

Необязательный атрибут `threads` у адаптера попадает в отчёт о времени.

## Логика решения

Одна для всех кандидатов, живёт в `evalkit/quality.py`.

Конвейер кадра: загрузка (Pillow, `ImageOps.exif_transpose`, RGB) → люди (если задан `PeopleDetector`) → `detect` → лица с уверенностью ниже `det_score_min` отбрасываются → главное лицо (наибольшая рамка) → качество → `embed` → `Liveness` → косинус с эталоном → порог.

Порядок проверок и статусы (одни и те же для эталона и кадра, пороги разные):

1. `multiple_people` — детектор людей насчитал ≥ 2 человек (с порогом `PeopleDetector.threshold`).
2. `no_face` — лиц нет.
3. `multiple_faces` — второе лицо не меньше `second_face_ratio` от главного (по меньшей стороне рамки). Для эталона это 0,3 (любое заметное второе лицо), для кадра 0,5 (сравнимое с главным).
4. `too_small` — меньшая сторона рамки лица < `face_min_px`.
5. `turn_to_camera` — лицо обрезано краем (`inside_min`) или поза вне пределов: `roll`, затем `yaw`, затем `pitch`.
6. `low_quality` — резкость, яркость или контраст вне пределов.
7. Только для кадра: `spoof`, если `Liveness` дал меньше порога. Потом `no_reference`, если у человека нет эталона, иначе `match` или `mismatch` по порогу сходства.

Для эталона итог — `accept` или причина из пунктов 1–6.

Как считается качество (по главному лицу):

- **Поза.** Поза оценивается по 5 точкам, грубо, на средних антропометрических пропорциях, согласованных с шаблоном ArcFace. `roll` считается по оси «середина рта → середина глаз»: 180° — вверх ногами. `yaw` — по смещению носа от середины глаз относительно межглазного расстояния. `pitch` — по положению носа между линией глаз и линией рта.
- **Резкость** — дисперсия лапласиана на кропе лица 112×112 в оттенках серого.
- **Яркость и контраст** — среднее и СКО яркости центральных 60% кропа.

Пороги по умолчанию (`QUALITY_DEFAULTS`, с комментариями в коде) выбраны по здравому смыслу и известной практике. Под кадры пакета они не подгонялись:

| ключ | эталон | кадр | смысл |
| --- | --- | --- | --- |
| `face_min_px` | 112 | 64 | вход моделей 112; меньше ~64 px точность заметно падает |
| `second_face_ratio` | 0.3 | 0.5 | второе лицо, начиная с которого «несколько» |
| `inside_min` | 0.9 | 0.8 | доля рамки лица внутри кадра |
| `yaw_max` / `pitch_max` / `roll_max`, ° | 20 / 20 / 15 | 30 / 30 / 30 | «смотрит в камеру»; крен исправляет выравнивание |
| `sharpness_min` | 40 | 15 | дисперсия лапласиана; у резких лиц обычно сотни |
| `brightness_min` / `brightness_max` | 50 / 215 | 35 / 230 | темно / пересвет |
| `contrast_min` | 15 | 10 | «плоское» засвеченное лицо |

Общие: `det_score_min=0.5`, `crop_size=112`, `people_min_height_frac=0` (люди ниже этой доли высоты кадра не считаются; 0 — считать всех).

**Ролики** (`kind=clip`). Кадры выбираются с частотой `--clip-fps` (по умолчанию 4 к/с, не больше `--clip-max-frames`). Из папки берутся все кадры: у них нет меток времени. Каждый кадр проходит тот же конвейер.

Итог ролика:

- `multiple_people`, если максимум людей по кадрам ≥ 2;
- `multiple_faces`, если хотя бы в одном кадре два сравнимых лица;
- иначе берётся лучший кадр: сначала прошедшие качество, затем наибольшее сходство со своим эталоном. Его статус качества — итог, если качество не пройдено;
- затем `SequenceLiveness` по всем кадрам: меньше порога → `spoof`, сбой → `error`;
- затем живость лучшего кадра и сходство.

Чужие пары для ролика: под каждый чужой эталон берётся лучший кадр (максимум сходства среди кадров, прошедших качество).

## Что считается

1. **По каждому изображению** (`per_image.csv`): люди, лица, score, размер лица, межглазное расстояние, yaw/pitch/roll, резкость, яркость, контраст, liveness, сходство со своим эталоном, максимум с чужим и чей. Также статусы и причины для роли эталона и кадра, оценка против разметки (`ok`, `lenient`, `false_reject`, `false_accept`, `wrong_reason`, `spoof_accepted`, `critical`, `no_reference`, `error`) и время по этапам.
2. **Эталоны**: ожидание против результата. Отдельно синтетические плохие эталоны, сгенерированные в памяти из эталонов: пустая серая, шум, абстрактный узор, коллаж двух эталонов, лицо ~40 px на сером 1280×720, поворот 90° и 180° без EXIF, сильное размытие. Все должны быть отклонены.
3. **Кадры проходной**: матрица «ожидание × статус» и главные числа по каждому ожиданию. «Совпал с чужим» = кадр прошёл качество, и сходство с каким-то чужим эталоном ≥ порога (живость здесь не учитывается).
4. **Пары** (`pairs.csv`, без векторов):
   - `genuine` — кадр человека S ↔ эталон S;
   - `impostor` — кадр ↔ каждый чужой эталон (во всех источниках);
   - похожие — подмножество impostor по `--similar`, в обе стороны;
   - `ref_ref` — эталон ↔ эталон;
   - `spoof_own` — пропуск или экран ↔ свой эталон;
   - `clip_*` — то же для роликов.

   Метрики на пороге берутся по кадрам, прошедшим качество: свои — только `match`. Ещё в отчёте: распределения, зазор «мин. своих − макс. чужих», сетка порогов с шагом 0,02, диапазон порогов без ложных совпадений и сколько своих там принимается, самые похожие пары людей. Порог скрипт не выбирает.
5. **Подмена кадра эталоном**: эталон как кадр и его копии (JPEG q60, масштаб 0,5 и 0,75, кроп 90%, поворот 5°, яркость +20%, вписывание в 1280×720). Сходство с исходным эталоном против максимума честных пар «кадр — свой эталон». То же по dHash и pHash всего кадра и кропа лица (расстояние Хэмминга, 64 бита). Положительный зазор — правило «слишком похоже на эталон = подмена» работает.
6. **Повтор кадра**: копии кадра (JPEG q70, масштаб 0,75, кроп 95%, яркость +10%) против оригинала. Честные — разные кадры одного человека.
7. **Пропуска и другие подделки как кадр**: статус, сходство со своим эталоном, liveness, людей.
8. **Живость по кадру**: живые (`kind=gate` с лицом) против подделок (`badge`, `screen`, `print`), доли ошибок на пороге и сетка порогов. Эталон как кадр — отдельной строкой.
9. **Подсчёт людей**:
   - сколько кадров с `people=1` дали ровно 1;
   - матрица «ожидаемо × насчитано»;
   - синтетика в памяти: коллаж двух кадров проходной разных людей (ожидание 2) и кадр, уменьшенный вдвое на сером поле (ожидание 1);
   - строки `multi_person`.
10. **Ролики**: матрица «ожидание × статус», пары по роликам, покадровые данные в `clip_frames.csv`.
11. **Живость по нескольким кадрам**: живые ролики против роликов-подделок. Плюс статичные последовательности в памяти: 8 копий эталона или кадра с дрожанием ±3 px, масштабом ±1% и JPEG-шумом, имитация «фото перед камерой». Такие должны быть отклонены.
12. **Время на CPU** по этапам (люди, детекция, эмбеддинг, liveness, итого на кадр; декодирование файла и кадра видео; живость по ролику): медиана и p95 в мс. Кадров в секунду в один поток = 1000 / медиана; с `--parallel N` — замер в N потоках. Также размер входа и число потоков. Перед замером идёт один прогревочный кадр.

## Выходные файлы (`--out`)

`per_image.csv`, `pairs.csv`, `variants.csv` (подмена и повтор), `synthetic.csv` (плохие эталоны, синтетика людей, статичные последовательности), `clip_frames.csv` (если есть ролики), `summary.json`, `report.md`. Во всех — только пути или имена файлов, числа и статусы.

## Схема `summary.json` (`schema_version` 2)

На верхнем уровне:

- `run` — имя прогона, время, описание адаптеров (`name`, `model_version`, `threshold_default`, `threshold_used`), источники разметки (у приватных путь не пишется), действующие пороги `quality`, пары похожих, версии.
- `counts` — строки по видам и ожиданиям, ошибки, заведённые эталоны.
- `references` — по `ref_expected`: n, принято, отклонено, статусы; `errors`; `synthetic` — по вариантам.
- `gate` — `matrix` (ожидание → статус → n), `by_expected` с полями `n, matched, mismatch, quality_reason, spoof, multiple_people, no_reference, error, matched_other, ok, lenient, wrong_reason, false_reject, spoof_accepted, critical`, а также `errors` (строки с неверным или критичным исходом). Если в разметке есть `disputed` — ещё `disputed`: строки `file, subject, status, reason, sim_own, max_other_sim, max_other_subject, liveness, tags`; в `matrix` и `by_expected` они не попадают.
- `pairs`:
  - `threshold`;
  - `genuine` (`n, accepted, rejected, dist`), `genuine_by_expected`, `genuine_all_faces`;
  - `impostor` (`n, false_accepts, dist`), `similar`, `ref_ref`;
  - `gap`, `grid` (`t, genuine_accepted, genuine_n, genuine_ok_any_*, impostor_fa, similar_fa, ref_ref_fa`);
  - `zero_fa` (`impostor_max, with_ref_ref_max, t_min_grid, genuine_accepted_above_max, genuine_n`);
  - `hardest_impostors`.
- `replay_reference` и `replay_frame` — `variants`: `n, detected, sim_min, sim_median, statuses` и максимумы `img_d/img_p/face_d/face_p`. Также `replay_sim_min, honest_sim_max, sim_gap` и `hash.{img_d,img_p,face_d,face_p}.{replay_max, honest_min, gap}`.
- `spoofs` — n, статусы, `accepted`, распределение сходства, строки.
- `liveness` — `live` (`n, rejected, bpcer`), `spoof` (`n, accepted, apcer`), `reference_as_probe`, `grid`; `null`, если адаптер не задан.
- `people` — `expected_one`, `labeled`, `synthetic`, `multi_person_rows`, `clips`, `errors` или `null`.
- `clips` — `gate`, `pairs` (как выше), `n`, `frames` или `null`.
- `seq_liveness` — `live_clips`, `spoof_clips`, `static_synthetic`, `grid` или `null`.
- `timing` — `stages.{people,detect,embed,liveness,total}.{n, median_ms, p95_ms}`, `decode_image`, `decode_video_frame`, `seq_liveness_per_clip`, `fps_single_stream`, `parallel`, `input`, `threads` или `null` при `--no-timing`.

Распределения (`dist`) — это `{n, min, p05, median, p95, max, mean}`.

## Приватность

- Скрипт **никогда не пишет на диск и в stdout** изображения, кадры, кропы, эмбеддинги и хеши. Искажения и синтетика существуют только в памяти.
- Разметка вне репозитория (например `~/face-data/labels.csv`) считается приватной. В выводы попадают только имена файлов с номером строки (`L1#12/имя.jpg`), псевдонимы людей (`L1-S01`) и числа. Пути к папкам и `note` не выводятся.
- Сообщения об ошибках чистятся от путей.
- `face/eval/out/` в `.gitignore`. В Git идёт только текстовый отчёт, переписанный в `face/docs/`.

## Известные ограничения

- Поза по 5 точкам грубая. Некоторые детекторы находят перевёрнутое лицо как обычное, ставя точки глаз и рта «по-прямому». Тогда `rotate_180` проходит проверку эталона. Синтетика это показывает, и модулю нужна отдельная мера, например детекция на повёрнутых копиях.
- Метрики на пакете — 10 человек и 58 кадров. Это проверка на здравый смысл, а не статистика. На защите будут чужие лица.
- Кадры роликов из папки не имеют меток времени, частота выборки к ним не применяется.
- `--parallel` использует потоки одного процесса. Если адаптер не потокобезопасен (например, общий `cv2.FaceDetectorYN` с `setInputSize`), замер покажет ошибки.
