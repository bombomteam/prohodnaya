# Самопроверка перед защитой

Основание: US-01–US-19 из [пайплайна](system-workflow.md), исходный кейс и согласованная схема идентификации. Это сценарии команды, не официальный перечень С1–С22. Все пункты пока не отмечены: отмечать только после живого прогона с записью результата и версии коммита.

| Проверка | Истории | Ожидаемый результат |
| --- | --- | --- |
| Чистый клон, `.env`, HTTPS, `docker compose up` по инструкции | US-18 | Сервисы готовы, понятны способы входа; секретов в Git нет |
| Импорт Keycloak на пустом тестовом volume | US-19 | Realm construction, panel, audience access-api, три роли и тестовые аккаунты появляются воспроизводимо; пароли из окружения |
| admin1/manager1/controller1: вход, обновление, выход | US-19 | API принимает access token с нужным aud; роли различаются, токены не сохраняются в localStorage |
| Неверная подпись, exp, iss, aud; запрещённая роль | US-19 | 401/403, операция не выполняется; подмена роли на клиенте не помогает |
| Новый человек и эталон через UI | US-01–02 | Одна пригодная личность принимается; отсутствие/несколько лиц отклоняются |
| QR/enroll-код → ECDSA-ключ телефона → /enroll | US-03 | У рабочего нет пароля или аккаунта Keycloak; открытый ключ связан с правильным человеком |
| Повтор/истечение enroll-кода, чужой person_id | US-03 | Привязка отклонена, чужой человек не получает ключ |
| Контролёр создаёт вход, телефон подписывает nonce, камера снимает лицо | US-04 | Сервер проверяет обе части, атомарно открывает одну смену и сохраняет журнал |
| Чужое лицо, подмена nonce/направления, неверная подпись, timeout | US-05 | Понятный отказ/ошибка, нет новой смены, попытка сохранена |
| Одновременный запрос и повтор того же HTTP-действия | US-04–05 | Возвращается принятое решение сессии, второй переход смены не возникает; новое предъявление погашенного nonce отклонено |
| Подписанные пачки POST /locations | US-06 | Подпись и принадлежность проверены, точки только в своей открытой смене, повтор не удваивает историю |
| Подтверждённый выход и запоздалая точка | US-07 | Проверены новый nonce и лицо, смена закрыта; точка после закрытия отвергнута |
| Журнал, список внутри, запрет деактивации при открытой смене | US-02,08–09 | История содержит успехи/отказы, время входа корректно; деактивация отклонена |
| План из материалов и 3–4 зоны, калибровка через UI | US-10 | admin меняет, manager только читает, изменения сохраняются |
| Период, часы, один/несколько/все люди | US-11–13 | Фильтры одинаковы для зон/маршрутов, легенда различима, ноль отличается от малой активности, отчёт проверяем |
| Четыре обязательных вопроса и сводка | US-14–15 | Модель реально вызвана, числа совпадают с расчётами; пустой период не порождает выдумок |
| Внешняя → локальная модель конфигурацией; отказ провайдера | US-16 | Реальный второй вызов работает; ошибка понятна, нет скрытой внешней передачи в локальном режиме |
| Перезапуск и пересоздание контейнеров с сохранёнными данными | US-17 | Люди, ключи, смены, координаты и журнал сохранены; pending не становится разрешением |
| Симулятор на реальном API | US-06,10–13 | Виртуальные ключи через /enroll, подписанные пачки /locations, source=sim; показано открытие тестовых смен, нет прямой записи в БД |
| Ролевые запреты прямыми HTTP-запросами | Все | Рабочий не действует за другого; manager не пишет план; admin не проводит проход без роли controller |
| Полный сценарий на телефоне и планшете через HTTPS | US-01–13,19 | Нет необходимости ручных запросов; Keycloak также доступен по HTTPS |
| Документы и объяснение кода каждым участником | US-18 | Запуск, схема, 3–6 решений, локальная модель, ограничения и честный отчёт ИИ; небольшая правка выполнима |

Для каждого прогона записывать: коммит, устройство, тестовые данные без секретов, ожидаемое/фактическое поведение, найденный дефект. Использовать вымышленные персональные данные и фото команды с согласия вне Git. Не объявлять весь допуск выполненным по одному демотесту.

Ориентиры от старта: 1:30 конфигурация IAM или объявленный fallback; 3:30 auth.py; 5:00 первый сквозной проход; 7:00 заморозка и проверка. При fallback явно фиксировать отклонение от требования IAM и согласование организаторов.
