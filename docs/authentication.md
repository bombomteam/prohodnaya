# Аутентификация и права доступа

Статус: целевое поведение, интеграция ещё не реализована. Дополнительное требование пользователя — Keycloak или аналог. В проекте выбран Keycloak; исходный кейс не изменяется. Этот документ дополняет [пайплайн](system-workflow.md).

## Граница ответственности

Keycloak управляет аккаунтами, паролями, сессиями и ролями. FastAPI проверяет выданный access token и разрешает конкретную операцию. PostgreSQL приложения хранит людей, эталоны лица, средства подтверждения телефона, смены, координаты и журналы.

У записи человека есть уникальная связь `(issuer, sub)` с проверенным аккаунтом. Email и имя могут изменяться и не подходят в качестве ключа связи. Пароли, refresh token и внутренние таблицы Keycloak в БД приложения не копируются.

## Поток входа

React → Keycloak → вход пользователя → код авторизации → обмен с PKCE S256 → access token → запрос FastAPI → проверка токена → проверка прав и принадлежности ресурса → бизнес-операция.

React регистрируется как публичный клиент без client secret. Используются точные разрешённые redirect URI и Web Origins. Access и refresh token находятся в памяти приложения; не сохраняются в localStorage, URL и логах. Перед запросами выполняется обновление при необходимости; при невозможности обновления нужен повторный вход. Это соответствует принципам [официального JavaScript-адаптера Keycloak](https://www.keycloak.org/securing-apps/javascript-adapter).

FastAPI проверяет подпись доверенной библиотекой по ключам настроенного провайдера, допустимый алгоритм, `iss`, ожидаемый `aud`, `exp` и применимые ограничения времени. Audience API должен быть настроен в выдаваемом токене; факт наличия токена от того же realm недостаточен. ID token служит для входа клиента и не принимается вместо access token.

Роли берутся из проверенного, заранее согласованного claim. Где хранить роли Keycloak — realm или client roles — определить в конфигурации; бэкенд использует один описанный способ сопоставления. Проверка на React отвечает за удобство, окончательный запрет выполняется FastAPI.

## Роли и права MVP

Единая матрица разрешений, границы доступа и перечень React-экранов находятся в [спецификации ролей и интерфейсов](roles-and-interfaces.md). Бизнес-роли: `worker`, `controller`, `admin`, `manager`. Совмещение допускается; администратор приложения не становится администратором Keycloak и не получает право контролёра автоматически.

## Создание рабочего

Администратор через собственный React UI отправляет данные и эталон → FastAPI проверяет права и пригодность → сохраняет доменную запись → сервер создаёт или контролируемо связывает аккаунт Keycloak → сохраняет связь → рабочий выполняет вход и привязку телефона.

Два хранилища не имеют общей транзакции. Нужны состояние «ожидает привязки», ключ повторной операции и повтор/компенсация при частичном сбое. Незавершённая привязка не даёт рабочему доступ к произвольному человеку. Вызовы Admin API выполняются только бэкендом с минимальными необходимыми правами отдельной служебной учётной записи; её секрет никогда не передаётся React.

Пароли задаются/меняются средствами Keycloak; приложение не хранит их. Способ первоначального получения доступа рабочим нужно выбрать и описать до реализации. Консоль Keycloak используется для инфраструктурной настройки, но не заменяет обязательные интерфейсы управления людьми проекта.

## Отказы, отзыв и физический проход

- Нет токена или он невалиден: 401 и предложение повторить вход.
- Валидный токен без прав на операцию/ресурс: 403, без выполнения действия.
- Недоступен Keycloak: новый вход/обновление могут не работать. Уже выданный токен может проверяться локально при наличии доверенных кешированных ключей и действующего срока; неизвестный ключ или невозможность обязательной проверки не дают доступ.
- Logout, блокировка пользователя и изменение ролей не гарантируют немедленный отзыв уже выданного JWT при локальной проверке. До реализации определить короткий срок access token и требуемую политику дополнительной проверки/интроспекции; проверить её поведение явно.
- Локальная деактивация человека проверяется FastAPI при проходе независимо от срока JWT.
- Вход в аккаунт не является разрешением физического прохода. Нужны отдельное доказательство для попытки и сравнение лица; завершение сессии Keycloak не закрывает рабочую смену.

## Compose и воспроизводимость

Сервисы MVP: `frontend`, `backend`, `db`, `keycloak`; локальная модель добавляется отдельно. PostgreSQL может быть одним контейнером, но для приложения и Keycloak используются разные базы и роли доступа. Keycloak самостоятельно управляет своей схемой; миграции приложения не меняют её. PostgreSQL поддерживается как хранилище Keycloak: [настройка БД](https://www.keycloak.org/server/db).

Запуск: готовность PostgreSQL → инициализация отдельных баз/ролей → миграции приложения и запуск Keycloak с настройками realm → готовность FastAPI и React. В Git хранятся безопасные настройки realm, клиента и ролей; пользовательские пароли, служебные секреты и реальные аккаунты исключены. Все аккаунты и настройки переживают пересоздание контейнера с сохранённым volume.

Настройки: публичный URL Keycloak, realm, client ID React, доверенный issuer, audience API и разрешённые origins; секреты служебного клиента и БД доступны только соответствующим серверным сервисам. Публичный issuer должен быть одинаковым для браузера и проверки токена; внутреннее имя контейнера не подставляется вместо ожидаемого issuer. HTTPS, включая доступ с телефона к камере и геолокации, учитывается в инструкции стенда.

## Приёмка и замена

Проверить роли, вход/обновление/logout, неверные подпись/issuer/audience и сроки, чужие ресурсы, сбой Keycloak, частичную регистрацию, сохранность аккаунтов. В инструкции запуска нужны первоначальный администратор IAM, администратор приложения и способы входа каждой роли.

Согласованный аналог должен предоставлять OIDC, управление аккаунтами и ролями, сессии, постоянное хранение и воспроизводимое развёртывание. При замене повторно проверяются flow входа, issuer/audience, ключи, claims, logout и provisioning. Самописный endpoint выдачи JWT не считается эквивалентной заменой данного требования.
