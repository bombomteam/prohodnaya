# Передача частей для сборки системы

Чат-интегратор соединяет бэкенд, фронтенд, вход операторов (Keycloak) и модуль распознавания лиц. Каждая часть описывает себя здесь **по одному шаблону**, чтобы интегратор читал эти файлы, а не весь код. Описания потом сверяются с кодом в `main`.

## Файлы

Каждый пишет и коммитит **только свой** файл:

| Файл | Часть |
| --- | --- |
| `backend.md` | Бэкенд (FastAPI, PostgreSQL, миграции) |
| `frontend.md` | Фронтенд (интерфейсы ролей) |
| `keycloak.md` | Вход операторов (Keycloak: realm, клиенты, роли) |
| `face.md` | Модуль распознавания лиц и камера |
| `devops.md` | compose, пайплайн, стенд, домены |
| `INTEGRATION.md` | Сводный отчёт для интегратора (собирается из файлов выше и проверки кода) |

## Правила

- Только проверенные факты на последнем `main`. Не проверил — так и напиши.
- Ссылки на файлы и строки вместо пересказа. Большие куски кода не копируй.
- Для каждого контракта укажи **один** файл-источник правды.
- До 150 строк.
- **Никаких секретов:** пароли, токены, ключи — только имена переменных.
- Отдельный коммит `docs(handoff): <часть>`; перед push — `git pull --rebase`.

## Шаблон

```markdown
# <Часть>: передача для интеграции

Проверено на коммите: <hash>, <время>.

## 1. Статус по сценариям
| Сценарий | Статус: работает / заглушка / не начато | Как проверено |
Только сценарии твоей части. Полный список: заведение человека с эталоном; код привязки и привязка телефона; вход оператора; начало прохода; подтверждение с телефона; проверка лица; решение и открытие смены; выход; координаты; обстановка «кто внутри»; журнал попыток; аналитика; отчёты; помощник.

## 2. Где что лежит
Точки входа, конфиг, главные модули, тесты, документы — путь и одна строка «что это». Не больше 15 строк.

## 3. Что отдаю другим (контракт)
Метод, путь, вход, выход, коды ошибок. Источник правды: <файл>.

## 4. Что беру у других
От кого, какой эндпоинт или поле, в каком файле и строке вызывается.

## 5. Настройки
| Переменная | Зачем | Пример (без секретов) | Где задаётся: .env.example / compose / код |
Плюс порты, имена сервисов в compose, публичные адреса.

## 6. Как запустить и проверить
Команды запуска и тестов. Как убедиться, что работает: запрос и ожидаемый ответ.

## 7. Расхождения и заглушки
Что не совпадает с другими частями; где STUB / TODO / демо-данные; известные баги.

## 8. Что нужно от других частей
Кому и что конкретно.

## 9. Риски на защите
Что может сломаться при живой проверке судьями.
```
