# Использование ИИ

Две части: какие модели работают внутри продукта и как ИИ-ассистенты использовались при разработке. Только то, что подтверждается репозиторием; цифры взяты из других документов. Кто какой участок писал руками, здесь не заявляется: это объясняется на защите по коду. Отчёт фронтенда: [frontend/docs/ai-usage.md](../frontend/docs/ai-usage.md).

## 1. Модели в продукте

| Модель | Для чего | Где работает | Лицензия |
| --- | --- | --- | --- |
| SCRFD det_10g (InsightFace) | найти лицо и 5 точек | контейнер `face`, локально, GPU стенда (A10) | код MIT, веса только для некоммерческих исследований |
| ArcFace glintr100 (InsightFace, antelopev2) | сравнить лицо с эталоном 1:1, порог 0,68 | `face`, GPU | то же, некоммерческая |
| YOLOX-S (запасной YOLOX-Tiny) | сосчитать людей в кадре | `face` | Apache 2.0 |
| MiniFASNet V2 + V1SE | пассивная проверка «живости» по кадрам | `face`, GPU | Apache 2.0 |
| MediaPipe Face Landmarker | лицевые ориентиры в образе (роль в проверке по нескольким кадрам описана в коде `face/app/`, здесь не сверена) | `face` | Apache 2.0 |
| YuNet + SFace (OpenCV Zoo) | запасной вариант распознавания, в образе, по умолчанию не используется | `face` | MIT / Apache 2.0 |
| LLM помощника: локальная `qwen2.5:7b` через Ollama или внешний OpenAI-совместимый сервис | сформулировать ответ руководителю и сводку по готовым цифрам | контейнер `ollama` на GPU стенда (A10) или внешний сервис, только через `backend/app/llm/`; провайдер переключается в интерфейсе («Локальная» / «Внешняя») или `LLM_PROVIDER` | зависит от провайдера |

Версия набора лиц в ответах модуля: `face-v1:scrfd10g+glintr100`. Веса вшиты в образ при сборке, сеть при запуске не нужна. Обучения своих моделей не было.

Что модель решает, а что нет:

- Модуль лиц возвращает факты и `status`. Решение о проходе принимает бэкенд; любая ошибка модуля означает отказ.
- LLM не считает и не ходит в базу. Числа берёт система из `repositories/queries.py`, модель их формулирует. Нет данных, сбой или ответ не по формату: статус `no_data`, `unavailable` или `bad_response`, выдуманных цифр быть не должно. Для слоя `llm` это проверяется после слияния ветки помощника.
- Картинки и эмбеддинги в LLM не передаются по замыслу; проверить по коду слоя после слияния.

## 2. ИИ-ассистенты в разработке

Работали группы ИИ-агентов, каждая над своим участком; человек ставил задачу и принимал результат.

| Группа | Что делала | Как проверялось |
| --- | --- | --- |
| Интеграция: бэкенд | Claude Code по фазам `PRD-backend.md` §10: субагент `backend-coder` (Sonnet) пишет фазу, `phase-reviewer` (Opus) принимает по критериям и запретам PRD, поиск по коду делает `haiku-scout`. Правила в `CLAUDE.md` | автотесты в контейнере (`pytest`), тест `test_no_stubs.py` запрещает заглушки, один коммит на фазу |
| Интеграция: фронтенд | интерфейсы ролей, API-адаптер, стартовая страница с выбором роли, «Как проверить кейс», мобильная вёрстка | `node --test`, браузерные прогоны на ширинах 320–1024 px. Отчёт фронтенда: [frontend/docs/ai-usage.md](../frontend/docs/ai-usage.md) |
| Интеграция: инфраструктура | compose-стенд, CI/CD, выкатка и откат, GPU для `face` и `ollama` (по заметкам передачи DevOps, детали сессий не зафиксированы) | прогоны на тестовом стенде, зелёный и красный CI ([pipeline.md](pipeline.md)) |
| Группа ИИ: модуль лиц | подбор моделей, оценка, антиспуфинг; по заметкам одновременно шли до 9 агентов. Замеры `face` на видео команды и на двух пакетах кейса; ускорение обработки кадров без смены решений | общий скрипт оценки `face/eval/run_eval.py`, автотесты `face/tests`; цифры в `face/docs/` |
| Группа ИИ: LLM помощника | выбор модели по замерам на стенде: три модели `qwen2.5` на одних вопросах, правка промптов; выбрана `7b` | таблица замеров в [local-model.md](local-model.md): выдуманных чисел 0, ложных `bad_response` 0 |
| Проверяющие | после каждого деплоя отдельные агенты проверяли стенд и сообщали о расхождениях | их отчёты шли координатору; сквозной пропуск своим лицом остаётся за живым человеком ([limitations.md](limitations.md)) |
| Эти документы | Claude подготовил Д8 по файлам репозитория и заметкам передачи | факты сверены с файлами; команды не запускались на чистой машине |

Что зафиксировано об ошибках ассистентов (только то, что есть в репозитории):

- Помощник: до правки промптов все три модели ошибочно отвечали «данных нет» на вопрос «кто вчера отработал меньше N часов», две приписывали людям время ухода и выдумывали список отказов ([local-model.md](local-model.md)). После правки промптов на 8 вопросах выдуманных чисел нет; модель выбрана по этим замерам.
- Фронтенд: проверка в браузере нашла переполнение таблицы сотрудников на узком экране и карточки рабочего на планшете; CSS исправили и повторили. Повторный просмотр сценария показал, что статус смены на телефоне не обновлялся без перезагрузки; добавили опрос.
- Фронтенд: первоначальный выбор WebAuthn для рабочего не совпал с решением команды (ECDSA через WebCrypto); адаптер заменили, старый `webauthn.js` не импортируется.
- Модуль лиц: в истории есть исправление падения `verify/camera` с ошибкой 500 на каждом вызове (`552dcdc`).
- Общее: на штатных порогах моделей лиц двойники проходили (32 ложных из 468 пар на пороге 0,40), поэтому порог подобран по данным и принято правило галереи ([face/docs/03-stack.md](../face/docs/03-stack.md)).

Какие ошибки ассистента найдут на защите при разборе кода, здесь не заявляется: выдумывать их не будем.
