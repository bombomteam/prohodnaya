# Вход и права через Keycloak

Это дополнительное требование пользователя, отсутствующее в исходном кейсе: использовать Keycloak или аналогичный сервер идентификации. Выбран Keycloak. Контракт: [аутентификация](../../docs/authentication.md). Прочитай его перед изменением входа, ролей, аккаунтов или развёртывания.

- Keycloak владеет аккаунтами, паролями, сессиями и ролями. Приложение хранит доменные данные и уникальную связь `(issuer, sub)` с человеком. Не создавай параллельный вход с локальными паролями или самописный JWT вместо IAM.
- React — публичный OIDC-клиент: Authorization Code Flow с PKCE S256, без client secret; разрешённые redirect URI и origins заданы явно. Токены храни в памяти, не в localStorage и не в логах.
- FastAPI проверяет access token: подпись, доверенный алгоритм и ключи, issuer, audience и сроки. Простое декодирование JWT не является проверкой. Не используй ID token для доступа к API.
- Роли `worker`, `controller`, `admin`, `manager` и принадлежность ресурса проверяются сервером. Роль из тела запроса не доверенная; рабочий не может запросить или изменить чужую смену.
- Ошибки токена дают 401, недостаточные полномочия — 403; при недоступности проверки не разрешай доступ по умолчанию. Документируй кеш ключей и задержку применения отзыва сессии/изменения ролей.
- Keycloak — отдельный контейнер с постоянной PostgreSQL БД, изолированной от БД приложения базой и пользователем. Конфигурация realm/клиентов/ролей воспроизводима и не содержит секретов.
- Создание аккаунта и человека не атомарно между двумя системами: используй явное состояние привязки, идемпотентность и восстановление после частичного сбоя. Не связывай произвольный `sub` из непроверенного клиентского поля.
- Access token подтверждает вход в приложение. Проход требует отдельного свежего доказательства и серверного сравнения лица. Logout не закрывает смену.
- Проверяй вход, обновление, logout, неверные подпись/issuer/audience, просроченный токен, отсутствие роли, чужой ресурс, частичный сбой регистрации и сохранность аккаунтов после перезапуска.

Замена допустима согласованным OIDC-провайдером с теми же свойствами. Она требует проверки настроек, claims ролей и сценариев; одной смены URL недостаточно.

## Матрица прав и экраны

Перед изменением ролей, прав или UI прочитай [роли и интерфейсы](../../docs/roles-and-interfaces.md). Используй единую матрицу и описанные экраны; проверяй права на сервере и принадлежность ресурса. Совмещение ролей объединяет разрешения, но `admin` не получает автоматически права `controller` или администратора IAM. Назначение повышенных ролей не доступно обычному пользователю приложения.
