# Два контура идентификации

Прочитай [контракт](../../docs/authentication.md) и [матрицу прав](../../docs/roles-and-interfaces.md). Исходный кейс и решения команды из файлов 00–08 определяют поведение; пока этих файлов нет в checkout, не придумывай их детали.

- Keycloak обслуживает только `admin`, `manager`, `controller`. Realm `construction`, public client `panel`, Code Flow + PKCE S256, audience `access-api` через mapper. Рабочего в Keycloak не создавать, роль `worker` не добавлять, provisioning через Admin API для рабочего не реализовывать.
- React хранит токены операторов в памяти, отправляет access token. FastAPI `current_user` проверяет JWKS, алгоритм, exp, iss, aud; `require_role` и доменный сервис проверяют роль и ресурс. Ответы: 401 «Сессия истекла, войдите заново», 403 «Недостаточно прав».
- JWKS получать через `KC_INTERNAL_URL`, issuer проверять по `KC_PUBLIC_URL` и realm; не подменять issuer внутренним hostname. Оба адреса конфигурируемые. Access token около пяти минут не означает мгновенного отзыва.
- Рабочий получает одноразовый enroll-код; WebCrypto создаёт неизвлекаемый ECDSA-ключ, `/enroll` регистрирует открытый ключ. Подпись nonce и сравнение лица подтверждают проход; подписанные пачки `/locations` подтверждают источник координат. Форматы брать из 01–08; не подменять ECDSA протокол WebAuthn без решения команды.
- Код регистрации потребляется атомарно; подпись, срок, контекст, отзыв и защита от повтора проверяются сервером. Рабочий не выбирает чужую смену через person_id.
- Compose: Keycloak 26.x, импорт realm, постоянное хранение, HTTPS для приложения и Keycloak. Экспорт не содержит credentials, парольных хешей или секретов; bootstrap получает их из окружения. Проверять импорт на пустом хранилище.
- Если к 1:30 от старта Keycloak не работает, команда явно включает fallback `/login` + JWT с теми же тремя ролями. Не объявлять его эквивалентным выполнением требования IAM; отразить ограничение и согласование. Рабочий остаётся на ключе.
- Проверить три роли, неверные токены, запреты, чужой ресурс, повтор enroll/nonce/пачки, смену после logout и отказ сервисов. Для сдачи использовать [чек-лист](../../docs/acceptance-checklist.md).
